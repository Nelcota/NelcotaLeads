## Verified as correct

- Every input-taking server function has a Zod validator; ORDER BY uses a whitelist; no `sql.raw`.
- Places and mail daily limits use the atomic `reserveRequest`; days are Brazil time, midnight included.
- DeepSeek calls have 90 s timeouts and Zod-parsed output; site fetches have timeouts and a 1.5 MB cap.
- `MAX_ATTEMPTS` (3) < `max_retries` (5) and the DLQ marks dead leads, so searches finish.
- `place_id` dedupe, below-minimum discard, one follow-up after 3 days, reply matching by thread first.
- `encodeHeader`, base64 SMTP bodies with dot-stuffing, escaped IMAP `LOGIN`.
- The only `dangerouslySetInnerHTML` is a constant; external links carry `rel="noreferrer"`.
- No floating promises (`no-floating-promises` is an error in oxlint); mutations disable their buttons while pending.
